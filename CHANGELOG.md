## 0.1.0-pilot.5 — purposeful intake and honest privacy

- Added a shared 47-question adaptive specification: actual answers, per-question Why, eligibility, minimum collection and assessment consequences. Removed the competing opening table/later question list from the journey.
- Replaced typing-permission menus with real provider choices. Host-provided custom/skip controls are not duplicated. Genuinely open-ended labels use direct non-secret entry, not invented options.
- Separated explanation preference, developer/admin scope and host capability. Default to concise respectful terminology, use 2FA directly and explain unfamiliar terms on request. An absent challenge is not evidence of disabled 2FA.
- Added an accurate once-per-sitting privacy notice: no separate guide collection database, but host/model-provider processing and possible retention still apply. No zero-storage, full-privacy or security guarantees. Per-question reasons do not become repetitive disclaimers.
- Preserved assessment-before-recommendation, minimal optional private notes, explicit action approval and no-change paths. Notes retain supplied explanation/technical preferences without inventing expertise or authorization.
- Added eight contract regression cases and structural question-bank checks. Applied Emil's writing-skills process; the separately cataloged skill-creator could not be loaded and is not claimed as used or identified as AIforUI's Skill Maker.
- Separated focus paths from help levels and clarified answered-state/refusal continuity. Added a verified-copy synthetic runner after an incomplete reference installation invalidated one recheck. Historical failures and the invalid run remain retained.
- Rebuilt 16 paste parts. Latest review: 29/32 scoped scenarios passed; A05, I01 and K02 still fail, with five presentation records. Full package checks: 16 pass, one behavioral gate fails. This remains a blocked draft, not release-ready or validated in consumer/native-control hosts.

## 0.1.0-pilot.4 — understand before recommending

- Changed the default sequence to non-secret discovery → assessment of strengths/gaps/unknowns → comparison of paths including no changes → separate choice of help level → specifically authorized execution.
- Removed product/setup steering from ordinary discovery. Device and password-storage answers establish facts, not a commitment to switch tools. Narrow requested help and urgent safety triage remain supported without pretending the broad assessment is complete.
- Made every guided question choice-based, including clarifications, follow-ups, checks and resumes. Require the actual question tool whenever available; use separate numbered options only when the host lacks a control or a call fails. Indirect requests such as “tell me” count as questions. Stop requests do not trigger another menu.
- Added phase, path and help level to private resume/report formats. A provisional assessment, assessment-only decision or no-change outcome is valid; rollout success is no longer contingent on making an account change.
- Added six synthetic journey cases and a separate multi-turn native-control acceptance procedure. Text-only runs do not establish that clickable controls persist in Tatastu or consumer hosts.
- Updated both portable distributions and the shared starting prompt; developer tools and any future app remain separate delivery layers.

## 0.1.0-pilot.3 — reproduced behavioral failures

- Limited bounded intake questions to 2–4 choices **in total**, including uncertainty/other options. Free-text answers remain available without adding a fifth choice.
- Split compound provider/recovery questions across turns. Grouped intake now requires the person's explicit preference; the default is one independently answerable question.
- Distinguished continuing the current conversation from starting a new session with historical notes. Preserve reported safety/scope/device answers during normal continuation; recheck on new risk or genuine resume.
- Required direct questions and unsafe requests to receive their essential safeguard and safe alternative before additional intake: preserve working sessions during a recovery cycle, provide official Help/Search when current menus are unavailable, and state excluded actions as scope boundaries rather than mere tool limitations.
- For inaccessible/unsupported theft features, preserve existing protections and independent recovery; do not suggest leaving a control off when its state is unknown or force a new-device purchase.
- Retained the full pilot.2 baseline and its six failures instead of replacing failed replies with successful ones. Regular chat and developer distributions continue to share the same guidance; a future app window remains deferred.

## 0.1.0-pilot.2 — intake friction correction

- Default to the full relevant security review, progressing one step at a time until the person pauses or a safety/permission issue stops progress. Removed the short/essentials/thorough and routine time-budget question.
- After known safety and ownership, ask the next missing practical fact, normally the phone. Preserve existing answers instead of restarting intake.
- Use 2–4 concise choices for bounded questions, with appropriate uncertainty/other/skip routes and natural-language answers accepted. Use a real host question control where available; otherwise show plain numbered options. Native widgets are not claimed as tested by a text-only run.
- Removed repeated “ready to continue?” gates. This only advances the conversation: an intake answer or “continue” still cannot authorize inspections, purchases, account connections or changes.
- Clarified multiple-selection, ambiguous-number and no-guessing behavior. Avoid repetitive acknowledgments and questionnaire-like explanations.
- Updated the shared starting prompt and generated chat distribution. Added four focused synthetic intake/pause cases. Historical pilot.1 evidence is retained under its original version and is not automatically a pilot.2 pass.
