# Agent and desktop boundaries

Read only the sections on your paths. Each item is a hypothesis to test, not a
finding.

## Agent applications

Map the principal for each action: human, active account, tenant, project, run,
tool and external credential. Then find the component that checks those identities
immediately before the effect. A well-worded system prompt is not that component.

Check these transitions:

1. **Evidence to instruction.** Retrieved pages, repository files, email, attachments,
   memory and tool results remain untrusted when summarized, copied or resumed.
   Provenance must survive transformations. Test an inert injected instruction in
   the lowest-trust input rather than placing it directly in the user's request.
2. **Intent to authority.** A request to inspect a billing integration is not a
   request to issue refunds. Bind approval to principal, operation, target, payload
   and expiry; recheck when these change. No approval is inferred from a timeout.
3. **Tool to operating system.** Trace working directory, arguments, environment,
   filesystem mounts, network destinations, inherited descriptors and subprocess
   lifetime. Shell permission is powerful even if a named connector is restricted.
4. **Credential to consumer.** Give the intended adapter only what it needs. Check
   provider selection, account switching, child processes and errors for accidental
   credential crossover. A refusal on one tool cannot be bypassed through another
   owner, host or private credential store.
5. **Queue to resumed effect.** After restart or reconnect, validate grants and
   membership again. A persisted task records intent; it does not make revoked
   authority permanent. Test cancellation and duplicate delivery as well.
6. **Model output to application input.** Validate structured outputs and escape
   markup. Tool names, URLs and command arguments generated by the model are inputs.
   Isolate retrieved indexes and caches by their real authorization context.
7. **One adapter to every supported route.** Shared policy needs one owner;
   claim a route protected only after a probe through that route. Do not infer
   parity from a common interface or a test of only the default model.
8. **A bounded task to cumulative consumption.** A token hint, retry count or
   per-turn limit may not bound aggregate calls, fan-out, paid tools or child jobs.
   Confirm where the total budget is enforced and what happens at exhaustion.

Safe probes use fake tools that record attempted effects. Check that the prohibited
effect did not occur, not merely that the assistant said it refused. Repeat a probe
through a real supported route before claiming that route is protected. Label
headless injections, scripted providers and self-reported outcomes accurately.

## Desktop applications

Inventory each window, embedded browser, preload, custom protocol, local server,
extension, child process and updater. Local and remote content can share a machine
without sharing trust.

- Check the runtime's isolation controls, navigation policy and permission handlers.
  Trace IPC caller identity **and** frame identity **and** requested operation.
  A loopback hostname or a `file:` URL alone does not establish the authorized caller.
- For paths, inspect both grant authorization and the eventual filesystem open.
  String prefix checks miss canonicalization and symlink races. Bounded, revocable
  grants need owner teardown and stale-URL tests, with renewal by an authorized owner.
- Verify handlers for external links and protocol URLs parse structured URLs, scope
  schemes and destinations, and do not interpret attacker strings as shell syntax.
- Inspect debug ports, Node/runtime switches and entitlements in a disposable
  packaged build. A development profile is not packaging evidence. Test legitimate
  helper processes before removing a fuse or entitlement they require.
- Examine actual release contents for accidental credentials, private data, maps,
  debug routes and unnecessary internal assets. Readability itself is a distribution
  decision. Integrity checks and signatures address tampering, not confidentiality.

For Electron, use the current vendor security checklist linked in
[sources](sources.md). A documented unsandboxed preload is a residual risk: rate it
by its reachable paths and compensating controls, and never flip the setting
without testing the preload code that needs it.
